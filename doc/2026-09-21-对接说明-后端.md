# 出租车终端对接说明（后端 → 嵌入式）

> 配套文档：《出租车终端通信协议》V1.0（协议文档.md）
> 联调脚本：`terminal_sim.py`（模拟终端，可反向联调）
> 版本：2026-09-21

---

## 1. 连接参数

| 项 | 值 | 说明 |
|---|---|---|
| 协议 | TCP 长连接（明文，无加密） | |
| 服务器地址 | `115.29.177.207` | 联调阶段用内网 IP 即可 |
| 端口 | `8899` | 需在云安全组/防火墙放行 |
| 心跳 | 由 `0x0200` 每秒一帧维持 | 服务器 `heartbeat-timeout-sec=30`，超过 30 秒无数据判离线 |
| 断线重连 | 建议 3~5 秒退避重连 | 若固件支持建议写入 |

> 注意：平台当前不做接入鉴权，设备 TCP 连接成功即视为在线；请在正式环境确认安全策略。

## 2. 平台已支持的消息

| 消息 ID | 方向 | 平台行为 | 终端要求 |
|---|---|---|---|
| `0x0200` 位置报警信息汇报 | 终端→平台 | 更新 `vehicle_location`；**bit0（烟雾/紧急）→ 紧急报警**、**bit2（疲劳）→ 疲劳报警**、**速度 > 80km/h → 超速报警**，实时推送；回执 `0x8001`；轨迹按 10s 节流落库 | ①TCP 连接立即 1 帧；②GPS 定位成功后每秒 1 帧；③状态变化立即上报；④速度真实上报（km/h） |
| `0x0210` 身份验证请求 | 终端→平台 | 按卡号/身份码匹配驾驶员档案，写 `auth_record`，回执 `0x8110` | 卡号 4B + 身份码 ASCII |
| `0x0001` 终端通用应答 | 终端→平台 | 记录应答日志 | 收到平台 `0x8001~0x9FFF` 后自动回复 |
| `0x8001` 平台通用应答 | 平台→终端 | 对终端上报帧应答（回显流水号） | 终端可忽略或记录 |
| `0x8110` 身份验证应答 | 平台→终端 | 验证裁决 | **`0x00` = 通过（开门）；`0x01` = 失败。注意与直觉相反，勿写反** |
| `0x8210` 疲劳驾驶控制 | 平台→终端 | 置/清疲劳标志 | `0x01` 蜂鸣间歇响；`0x00` 恢复 |
| `0x8811` 蜂鸣器控制 | 平台→终端 | 远程开/关蜂鸣器 | `0x01` 开；`0x00` 关 |

**暂不支持**：分包（消息体属性 bit13 必须为 0，封装项必须 `0x00000000`）。

## 3. 需要嵌入式回填 / 确认的事项（联调前置）

> 以下为嵌入式侧回填结论（2026-09-21），均已落实：

1. **终端映射表** ✅ 已确认
   - 终端 ID / 手机号均为 `091111222200`（BCD，两字段相同）
   - 按测试映射接入：`091111222200 → ZD2026001001 / 浙A·T3236`
   - 暂无其他终端；后续有真实终端时提供「终端 ID → device_no + 车牌」清单，平台改数据库映射。

2. **速度字段** ✅ 已确认（方案一）
   - 终端真实上报速度：GPS 地面速度（RMC 语句，节→km/h），填 `0x0200` 速度字段
   - 平台已实现超速报警：`app.netty.overspeed-kmh=80`，超过 80km/h 生成 `alarm_type=1` 超速报警并实时推送
   - 演示环境静止时速度在 0 附近属正常。

3. **时间字段** ✅ 已确认
   - `0x0200` 时间字段按 BCD `YYMMDDhhmmss`、UTC 上报；平台入库 +8 转北京时间。

4. **真实帧样例** ⏳ 联调首日提供
   - GPS 更新、按键报警、刷卡三种场景的原始 hex 帧各几帧，用于核对编解码。

## 5. 联调验收清单（两端都跑通即算完成）

- [ ] 终端 TCP 连接建立，平台日志出现「终端接入」
- [ ] 连接即收到首帧 `0x0200`，后续 1 秒/帧
- [ ] 平台回执 `0x8001`（回显终端流水号）
- [ ] 平台下发 `0x8210/0x8811`，终端收到并有动作（蜂鸣/疲劳）
- [ ] 终端触发报警位（bit0/bit2），平台生成报警并推送前端
- [ ] 终端速度 > 80km/h，平台生成超速报警并推送前端
- [ ] 终端上报 `0x0210`，平台回 `0x8110`，`0x00` 时开门
- [ ] 断开终端 30 秒后，平台侧该车置为离线
