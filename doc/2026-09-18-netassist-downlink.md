# 用「网络调试助手」做平台下发 —— 操作手册

- 日期：2026-09-18
- 目的：不启动 `fake_platform.py`，直接用 share 目录下的 `网络调试助手.exe` 充当平台，把「平台 → 终端」的指令发下去
- 适用：课题一 出租车智能定位终端 现场演示 / 单点功能验证

---

## 0. 先搞清楚谁连谁（最容易搞反）

**终端是 TCP 客户端**，程序启动后会主动去连 `terminal/deploy/config` 里配的 `server_ip:server_port`。

所以：

> **网络调试助手必须开「TCP Server」，监听 8888 端口，等板子来连。**
> 如果开成 TCP Client，板子连不上，什么都不会发生。

方向搞对了，后面所有步骤才有意义。

---

## 1. 网络检查（30 秒）

| 设备 | IP |
|---|---|
| PC 有线网卡 | `192.168.1.101` |
| 板子 eth0 | `192.168.1.103` |
| （平台如果跑在 Ubuntu） | `192.168.1.102` |

在 PC 的 cmd 里：

```
ipconfig
ping 192.168.1.103
```

- `ipconfig` 里要有 `192.168.1.101`
- `ping` 要能通

不通就先解决网络，别急着开助手（板子开机卡死十有八九也是这一类问题）。

---

## 2. 助手设置（7 步）

1. 双击运行 `D:\shixiwenjian\嵌入式资料\share\网络调试助手.exe`
2. **协议类型** 选 **TCP Server**
3. **本地 IP 地址** 选 `192.168.1.101`（**不要选 127.0.0.1**）
4. **本地端口** 填 `8888`
5. 点 **「打开 / 监听」** —— 按钮变成「关闭」表示监听成功
6. **接收区** 勾上「十六进制显示」（看得清楚）
7. **发送区** 勾上「**十六进制发送**」 ← **这一步漏了会直接把十六进制当普通文本发出去，终端完全没反应**

> 不同版本的按钮文字可能略有差别，认准「TCP Server / 本地端口 / 打开 / 十六进制」这几个要素就行。

## 3. 终端侧启动

在 Xshell 的板子上：

```
cd /app_taxi/deploy
./bt.sh
cd /app_taxi
./taxi_terminal deploy/config
```

**成功的标志**（两个地方都要看）：

- **终端控制台**出现：
  ```
  connected to platform 192.168.1.101:8888
  ```
- **助手**那边出现「客户端连接」提示，客户端 IP 是 `192.168.1.103`，并且立刻收到一帧 `7E 02 00 ...`（这是终端连接建立后立刻上报的位置信息）

这两条都出现，链路就通了。

## 4. 下发指令速查表（直接复制「粘贴版」那一列）

| 消息号 | 作用 | 粘贴到发送框的十六进制 |
|---|---|---|
| `0x8210` | 疲劳驾驶 **ON** → 蜂鸣器周期响 + 红灯报警序列 | `7E8210000109111122220009111122220000010001000101937E` |
| `0x8210` | 疲劳驾驶 **OFF** → 解除报警 | `7E8210000109111122220009111122220000010001000100927E` |
| `0x8110` | 身份验证 **准许** → 数码管 PASS + 蜂鸣器短响 + 舵机开门 | `7E8110000109111122220009111122220000010001000100917E` |
| `0x8110` | 身份验证 **拒绝** → 数码管 FAIL | `7E8110000109111122220009111122220000010001000101907E` |
| `0x8811` | 蜂鸣器 **ON** → 持续响 | `7E8811000109111122220009111122220000010001000101987E` |

## 5. 演示流程（推荐按这个顺序）

| 步骤 | 你在哪操作 | 操作 | 预期 |
|---|---|---|---|
| 1 | 板子键盘 | 输 6 位身份码 → 按 `#` | 助手接收区出现一帧 `7E 02 10 ...`（身份验证请求） |
| 2 | 助手 | 发 **0x8110 准许** | 数码管 `PASS`、蜂鸣器「嘀」一声、舵机开门 |
| 3 | 助手 | 发 **0x8210 疲劳 ON** | 蜂鸣器周期响（300ms 响 / 300ms 停）+ 三色灯进报警序列 |
| 4 | 助手 | 发 **0x8210 疲劳 OFF** | 报警全停，状态灯回正常运行节奏 |
| 5 | 助手 | 发 **0x8811 ON**，等 3 秒，再发 **0x8811 OFF** | 蜂鸣器持续响，然后停 |

## 6. 怎么确认下发成功了（重点）

终端收到 `0x8001 ~ 0x9FFF` 区间的消息后，会**自动回一帧 `0x0001` 终端通用应答**。

所以在助手接收区：

- **每发一帧，下面立刻多出一行 `7E 00 01 ...`** → 下发成功 ✅
- 发完什么都没回来 → 帧不对（校验/长度/转义）或发送模式没勾十六进制 ❌

终端控制台上同步的打印：

| 你发的 | 终端控制台应出现 |
|---|---|
| `0x8210` ON | `[RX] FATIGUE: ON` |
| `0x8210` OFF | `[RX] FATIGUE: OFF` |
| `0x8110` 准许 | `[AUTH] PASS, door open` |
| `0x8110` 拒绝 | `[AUTH] FAIL` |
| `0x8811` ON | `[RX] BEEP control: ON` |
| `0x8811` OFF | `[RX] BEEP control: OFF` |
| `0x8001` | `[RX] PLAT-ACK: my_seq=1 msgID=0x8001 result=0 (OK)` |

**两头对上才算通**：助手有回帧 + 终端有打印。

## 7. 排错

### 7.1 「助手显示正在监听，但板子连不上」——先查 Windows 防火墙（实测第一高频原因）

判断方法（在 PC 上）：

1. 助手显示 `正在监听...` 且 `netstat -ano | findstr 8888` 能看到 `0.0.0.0:8888 LISTENING`
   → 助手自身没问题，绑定也正确（不是 127.0.0.1）
2. PC 上 `ping 192.168.1.103` 能通
   → 网络链路没问题
3. 但 `netstat -ano | findstr 8888` **只看到 LISTENING，没有 ESTABLISHED**
   → 板子的连接请求被拦在外面了，**就是防火墙干的**

查防火墙：

```
netsh advfirewall show allprofiles state
```

如果输出里 **「公用配置文件 状态 = 启用」**，那基本可以确定——板子那块有线网卡被 Windows 判成了「公用网络」，走了公用配置文件，入站连接被全丢。

**三种解决办法（按推荐顺序）：**

**办法 A（推荐，一劳永逸）：把网卡改成「专用网络」**
因为专用配置文件的防火墙本来就是关的，改完立即生效。

管理员 PowerShell：
```powershell
Set-NetConnectionProfile -InterfaceAlias "以太网" -NetworkCategory Private
```
或图形界面：设置 → 网络和 Internet → 以太网 → 点当前的网络配置文件 → 改成「专用网络」。

**办法 B：给 8888 加一条入站放行规则**

管理员 CMD：
```
netsh advfirewall firewall add rule name="taxi_terminal_8888" dir=in action=allow protocol=TCP localport=8888
```

**办法 C（演示救急，最粗暴）：临时关掉公用配置文件防火墙**
```
netsh advfirewall set publicprofile state off
```
演示完记得开回来：
```
netsh advfirewall set publicprofile state on
```

> **验证是否修好**：改完后板子 2 秒内会自动重连，助手界面应该出现「客户端连接」+ 客户端 IP `192.168.1.103`。

### 7.2 其他情况

| 现象 | 原因 | 处理 |
|---|---|---|
| 助手一直没有客户端连上 | 协议类型不是 TCP Server / 端口不是 8888 / 本地 IP 选了 127.0.0.1 | 按第 2 节逐项核对 |
| 终端一直刷 `[net] connect ... failed` | 助手没点「打开」，或防火墙拦了 8888 | 点「打开」；关掉 Windows 防火墙或放行 8888 |
| 板子 `deploy/config` 里 server_ip 不是 192.168.1.101 | 配置没改 | 改 `server_ip=192.168.1.101`（板子上直接 `vi` 改，NFS 实时生效） |
| 发出去终端毫无反应 | **没勾「十六进制发送」** | 勾上重发 |
| 助手接收区一直空白 | 该工具此前被验证存在「能连接但收发不显示」的问题，属工具自身缺陷 | 换 `amaoComV4.9.exe`，或直接跑 `python3 platform/src/fake_platform.py` |
| 看板子控制台的 `[net] connect ... failed (xxx)` 判断卡在哪 | xxx 是 `Connection refused` | 助手没在监听（点「打开」） |
| 同上 | xxx 是 `Connection timed out` | 连接请求被防火墙丢了 → 按 7.1 处理 |
| 助手有回帧，但蜂鸣器/舵机没动 | 板子驱动没加载 | 回 `[root@farsight]#`，重跑 `cd /app_taxi/deploy && ./bt.sh` |
| 助手关掉再打开后没反应 | 连接断了 | 终端会在 2 秒内自动重连，等它；助手记得重新「打开」 |

## 附录 A：这帧为什么长这样（逐字节拆解）

以 `0x8210 疲劳 ON` 为例：

```
7E                    帧头
82 10                 消息ID        0x8210
00 01                 消息体属性     低 12 位是消息体长度 = 1
09 11 11 22 22 00     终端手机号     BCD[6]
09 11 11 22 22 00     终端ID         BCD[6]
00 01                 流水号
00 01                 总包数
00 01                 包序号
01                    消息体         疲劳状态 = 1
93                    校验码         从「消息ID」到「消息体」逐字节异或
7E                    帧尾
```

三条规则：

1. **终端ID / 手机号从哪来**：`deploy/config` 里的 `terminal_id=091111222200`，两位一组当十六进制解析成 6 字节 → `09 11 11 22 22 00`。
2. **校验算法**：从消息ID的第一个字节开始，一路异或到消息体最后一字节，结果填在校验位。
3. **转义**：中间如果出现 `7E` 就改写成 `7D 02`，出现 `7D` 就改写成 `7D 01`（头尾的 `7E` 不动）。
   上表这些帧**恰好都不含 `7E`/`7D`**，所以不用转义，可以原样粘贴。

## 附录 B：想改终端ID / 流水号，校验怎么重算

把要发的字节（从消息ID开始，不含首尾 `7E` 和校验位）丢给下面这段算异或：

```python
b = bytes.fromhex("8210" "0001" "091111222200" "091111222200" "0001" "0001" "0001" "01")
x = 0
for v in b:
    x ^= v
print("%02X" % x)          # -> 93
```

拼接顺序就是：`消息ID + 长度 + 手机号 + 终端ID + 流水号 + 总包数 + 包序号 + 消息体`。

也可以直接改 `platform/tools/gen_downlink_frames.py` 里的 `PHONE / TERM / SERIAL / CASES`，重新生成全部帧：

```bash
python3 platform/tools/gen_downlink_frames.py
```

脚本自带「解码回灌自校验」——生成的每一帧都会再喂回同一套解码逻辑验一遍（长度域、异或校验、转义、消息体全都对上才会打印 `OK`），所以表里的帧可以放心直接用。
