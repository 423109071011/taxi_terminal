# 出租车终端通信协议文档 V1.0

> 依据 `shared/jt808.c/.h` 实现整理，消息号 0x0200/0x0001/0x8001/0x8811 严格按
> 《JH车载定位数据协议_V0.1》，0x0210/0x8110/0x8210 为小组自定义扩展。
> 实现文件：`shared/jt808.c`（组帧/解码）、`terminal/src/biz/taxi.c`（业务）。

---

## 1. 帧结构（总长 = 25 + 消息体长度 字节）

```
7E │ 消息ID │ 消息体属性 │ 终端手机号 │ 终端ID │ 流水号 │ 消息包封装项 │ 消息体 │ 校验码 │ 7E
   │  2B    │    2B      │  BCD 6B   │ BCD 6B │   2B   │    DWORD 4B  │ ≤1023B │   1B   │
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头标识 | 1B | 固定 `0x7E`（头尾各一个） |
| 消息 ID | 2B | 大端，见 §2 消息总表 |
| 消息体属性 | 2B | bit15~14 保留；**bit13 分包标志（本协议恒 0）**；bit12~0 = 消息体长度（大端低12位） |
| 终端手机号 | 6B | BCD 码，本项目固定 `09 11 11 22 22 00` |
| 终端 ID | 6B | BCD 码，本项目固定 `09 11 11 22 22 00` |
| 消息流水号 | 2B | 大端，终端侧发送后自增（`jt808_build` 内部自增） |
| 消息包封装项 | 4B | **不分包时必须为 `0x00000000`**（协议图1要求，勿漏，漏了终端整帧丢弃） |
| 消息体 | 0~1023B | 各消息定义见 §3 |
| 校验码 | 1B | **从消息 ID 到消息体末字节逐字节异或**（不含头尾 7E） |
| 帧尾标识 | 1B | 固定 `0x7E` |

### 转义规则（仅头尾 7E 不参与转义）

| 原字节 | 转义后 |
|---|---|
| `0x7E` | `0x7D 0x02` |
| `0x7D` | `0x7D 0x01` |

解码端逐字节流式解码：遇 `7E` 判定帧起/止；`7D` 后跟 `02` 还原 7E、`01` 还原 7D。
收到帧后校验两道：属性低12位长度 == 实际消息体长度；异或校验一致，否则整帧丢弃。

## 2. 消息 ID 总表

| 消息 ID | 名称 | 方向 | 触发时机 |
|---|---|---|---|
| `0x0200` | 位置报警信息汇报 | 终端 → 平台 | ①TCP 连接成功立即 1 帧；②GPS 定位成功后每秒 1 帧；③**状态变化（烟雾报警/开门/疲劳）立即上报**；④`uppath` 轨迹回放（200ms/帧） |
| `0x0001` | 终端通用应答 | 终端 → 平台 | 收到平台 `0x8001~0x9FFF` 任意下发消息后**自动回复** |
| `0x8001` | 平台通用应答 | 平台 → 终端 | 平台对终端上报帧的应答；终端打印 `[RX] PLAT-ACK ... result=0(OK)` |
| `0x8811` | 蜂鸣器控制（自定义） | 平台 → 终端 | 远程控制蜂鸣器开/关 |
| `0x0210` | 身份验证请求（自定义） | 终端 → 平台 | 刷卡或键盘输入身份码后发起 |
| `0x8110` | 身份验证应答（自定义） | 平台 → 终端 | 平台对 0x0210 的裁决，**PASS 时联动开门** |
| `0x8210` | 疲劳驾驶控制（自定义） | 平台 → 终端 | 置/清疲劳标志，联动蜂鸣器间歇响 |

## 3. 消息体定义

### 3.1 `0x0200` 位置报警信息汇报（34B = 28B 基本信息 + 6B 附加项）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4B | 报警标志 | bit0=烟雾超标（借用紧急报警位）；bit2=疲劳驾驶；其余 0 |
| 4 | 4B | 状态 | bit1=已定位；bit12=车门加锁；bit13=门1开（与 bit12 互斥）；bit18=GPS 定位 |
| 8 | 4B | 纬度 | 度 ×10⁶，大端（如 30.572815 → 0x01D29CEF） |
| 12 | 4B | 经度 | 度 ×10⁶，大端 |
| 16 | 2B | 高程 | 恒 0（未接气压计） |
| 18 | 2B | 速度 | 恒 0 |
| 20 | 2B | 方向 | 恒 0 |
| 22 | 6B | 时间 | BCD `YYMMDDhhmmss`，**UTC**（GMT+8 需 −8h；无 GPS 日期时用系统时间换算） |
| 28 | 1B | 附加项 ID | `0x01` = 里程 |
| 29 | 1B | 附加项长度 | `0x04` |
| 30 | 4B | 里程值 | 恒 0 |

### 3.2 `0x0001` / `0x8001` 通用应答（5B）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2B | 应答流水号 | **被应答那条帧头里的流水号**（原样回显） |
| 2 | 2B | 应答 ID | 被应答的消息 ID |
| 4 | 1B | 结果 | `0x00`=成功，其他=失败 |

### 3.3 `0x8811` 蜂鸣器控制（1B）

| 值 | 含义 |
|---|---|
| `0x01` | 蜂鸣器开 |
| `0x00` | 蜂鸣器关 |

### 3.4 `0x0210` 身份验证请求（4 + N B）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 4B | 卡号 | RFID 卡 UID，大端原样 |
| 4 | N B | 身份码 | 键盘输入的 ASCII 数字串（最多 6 位，无输入则无此段） |

### 3.5 `0x8110` 身份验证应答（1B）⚠️ 语义反直觉

| 值 | 含义 | 终端联动动作 |
|---|---|---|
| **`0x00`** | **验证通过（PASS）** | 数码管显 PASS + 舵机开门 90° + 蜂鸣短响一声 + `verified=1` + 刷新空闲计时 |
| `0x01` | 验证失败（FAIL） | 数码管显 FAIL，不开门 |

> ⚠️ **`00` 才是通过**——`taxi_handle_auth_resp` 判 `b[0]==0` 为 PASS，测试时极易写反。

### 3.6 `0x8210` 疲劳驾驶控制（1B）

| 值 | 含义 | 终端联动动作 |
|---|---|---|
| `0x01` | 疲劳 ON | `fatigue=1`，蜂鸣器线程间歇响 |
| `0x00` | 疲劳 OFF | 恢复正常 |

## 4. 典型交互时序

```
终端                                    平台
 │ ── TCP 连接 ──────────────────────────►│
 │ ── 0x0200 位置帧(seq=N) ──────────────►│   连接建立立即上报
 │ ◄── 0x8001 应答(seq=N, id=0200, 0) ────│
 │                                        │
 │ ◄── 0x8210 疲劳 ON(seq=M) ─────────────│
 │ ── 0x0001 应答(seq=M, id=8210, 0) ────►│   收到 0x8001~0x9FFF 必回 0x0001
 │ ── 0x0200(alarm.bit2=1) ─────────────►│   状态变化立即上报
 │                                        │
 │ ◄── 0x8110 PASS(seq=K) ────────────────│
 │ ── 0x0001 应答 ───────────────────────►│   舵机开门 90°，10s 空闲自动关门
```
