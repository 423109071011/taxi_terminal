# 出租车终端 · 答辩演示脚本（2026-09-21）

> 目标：10~15 分钟内把实验全部功能点过一遍。每一步都给出【操作 → 预期现象】。
> 提前准备：网络调试助手（Server 8888，已 Listen）、测试帧清单（本文档 §5）、
> 轨迹演示文件 `/tmp/path.txt`（§6 有现成内容）、RFID 卡一张、烟雾源（打火机不点火放气）。

---

## 0. 开场一句话

「基于 FS6818 开发板的出租车终端：自研 Linux 字符设备/杂项设备驱动 7 个 +
用户态多线程应用，按类 JT808 协议与平台 TCP 双向通信，实现定位上报、
身份认证开门、疲劳/烟雾报警、历史轨迹回放。」

技术栈要点（答辩加分区）：
- 驱动层：矩阵键盘(i2c)、蜂鸣器(GPIO)、舵机(PWM+工作队列)、ADC(misc)、RFID、LED
- 应用层：`hal/`(设备抽象) + `biz/`(业务) + `svc/`(网络/命令/分发) 三层，pthread 多线程
- 协议：22 字节帧头（消息ID+属性+手机号BCD+终端ID+流水号+封装项）、0x7E/0x7D 转义、异或校验
- 工程：Git 版本管理、交叉编译、NFS 根文件系统开发、开机自启脚本

## 1. 系统启动与驱动加载（2 分钟）

板上演示：
```bash
reboot   # 或直接看当前已启动状态
/arduino_drivers/run_taxi.sh
```
**预期串口输出**（逐条讲）：
```
[run_taxi] running private copy /tmp/.taxi_run_xxx   ← 安全启动设计：NFS 上不覆盖运行中的可执行文件
[cfg] loaded /arduino_drivers/taxi.conf -> platform 192.168.1.101:8888   ← 配置外置，换平台只改配置
key: using /dev/input/event4 (i2cKEY)                ← 键盘驱动枚举
<beep> GPIOC29 request successfully                  ← 蜂鸣器驱动
<servo> GPIOC7 request successfully                  ← 舵机驱动
gps: ...                                             ← GPS 热插拔降级
connected to platform 192.168.1.101:8888             ← TCP 连上平台
```

## 2. 平台 ↔ 终端 双向链路（2 分钟）

1. 调试助手接收区：**立刻收到一帧** `7E 02 00 ... 7E`（0x0200 位置帧，连接即报）。
2. 指出帧结构：`7E | 0200 | 0026 | 091111222200(手机号) | 091111222200(终端ID) | 流水号 | ... | 校验 | 7E`。
3. 板上敲 `info`：
```
net_ok=1 door_open=0 verified=0 fatigue=0
gps: lat=... sats=... status=...
card: ... has_card=0
```

## 3. 平台下发控制（核心联动，3 分钟）

在调试助手发送区逐条粘贴发送（发送格式选 HEX）：

| 顺序 | 粘贴内容 | 板上预期现象 |
|---|---|---|
| ① 疲劳 ON | `7E8210000109111122220009111122220000010000000001937E` | 蜂鸣器间歇响；`info` 里 `fatigue=1`；助手收到 0x0001 应答帧 |
| ② 疲劳 OFF | `7E8210000109111122220009111122220000020000000000917E` | 蜂鸣器停 |
| ③ 认证 PASS | `7E8110000109111122220009111122220000050000000000957E` | 数码管显 PASS + 舵机开门 90° + `verified=1` |
| ④ 认证 FAIL | `7E8110000109111122220009111122220000060000000001977E` | 数码管显 FAIL，不开门 |
| ⑤ 蜂鸣 ON | `7E88110001091111222200091111222200000300000000019A7E` | 蜂鸣器长响 |
| ⑥ 蜂鸣 OFF | `7E88110001091111222200091111222200000400000000009C7E` | 蜂鸣器停 |

> 讲点：每条下发终端都回 **0x0001 终端通用应答**（回显流水号）——协议闭环。

## 4. 本地外设演示（3 分钟）

| 项 | 操作 | 预期 |
|---|---|---|
| 舵机手动 | `servo`（无参数） | 0→90→180→90→0 扫动，每步打印 `ioctl ret=0` |
| 矩阵键盘 | 按 `0~9` | 数码管滚动显示；`A/B` 翻页 |
| RFID | 刷卡 | 串口 `[刷卡] 卡号 XXXXXXXX，车门打开` + 舵机开门；**按 `C` 键关门**（设计即"刷卡开门、按键关门"，无自动关门） |
| ADC 烟雾 | 打火机放气凑近传感器 | 读数陡增 → `smoke_alarm=1` → 蜂鸣器响 + 状态变化立即上报一帧 |
| LED | 观察状态灯 | 网络通/断两种闪烁模式 |

## 5. GPS 定位与位置上报（2 分钟，含室内兜底方案）

**如实说明**：GPS 需天线见空，室内演示搜不到星；系统设计了**无 GPS 降级**与**历史轨迹回放**两条兜底路径。

1. 展示降级能力：`info` 显示 `gps ... status=0`（搜星中），程序一切功能照常 ——「热插拔设计」。
2. **历史轨迹回放**（`uppath` 命令，逐点发 0x0200）：

板上：
```bash
cat > /tmp/path.txt << 'EOF'
30.572815,114.305539
30.574100,114.307700
30.575600,114.309900
30.576800,114.312100
EOF
uppath /tmp/path.txt
```
**预期**：调试助手按 200ms 间隔连收 4 帧 `7E 02 00 ... 7E`，帧内经纬度字段是真实武汉坐标 —— 演示「位置上报协议链路 + 轨迹上传功能」完整跑通。

3. 有条件时（天线到窗边）：等 `info` 出 `status=1 sats≥4`，助手每秒自动收一帧实时位置。

## 6. 收尾讲工程化（1 分钟）

- `git log --oneline`：展示开发迭代与修复记录（配置静默失效、NFS 覆盖内核 Oops、舵机 GPIO 泄漏三大典型 bug 的定位与修复）——「问题定位能力」的最好证明。
- 换平台只需改 `/arduino_drivers/taxi.conf` 一行；驱动/应用/配置全在 Git 仓库。
- 文档齐备：下发帧清单、联调手册、生成脚本（`doc/` 目录）。
