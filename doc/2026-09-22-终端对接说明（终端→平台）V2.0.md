# 车载定位终端对接说明（终端 → 平台）V2.0

> 更新日期：2026-09-22。适用固件：`taxi_terminal` md5 以最新构建为准（2026-09-22 20:55 起，卡号换算版）。
> 本文档以终端**实际实现**为准；与早期版本的区别见文末"变更记录"。终端协议已随前一平台联调验收在线运行，平台侧请按本文档对齐解析。

---

## 1. 接入方式

- 终端为 **TCP 客户端，主动连接平台**；接入参数（服务器 IP / 端口）外置在终端配置文件 `taxi.conf`，改配置重启程序即接入，无需重新烧录。
- 终端心跳 1 秒/帧，请平台侧 TCP 读空闲超时 ≥ **180 秒**。
- 终端断线后每 **2 秒**自动重连，平台服务重启无需通知终端。
- **不要求** 0x0100 注册 / 0x0102 鉴权流程（终端未实现，平台无需等待这两个消息）。

## 2. 终端身份参数

| 项 | 值 |
|---|---|
| 终端 ID（帧头 6B，BCD） | `091111222200` |
| 终端手机号（BCD） | 未单独配置，**同终端 ID** `091111222200` |
| 车辆 | 浙A·T3236（编号 ZD2026001001） |
| 测试卡号（RFID UID，大端 4B） | `0D 0E 0F 10` → 四字节大端换算十进制 = **219025168** |

> **卡号换算规则（2026-09-22 生效）**：卡号统一按 **4 字节大端合成 32 位整数 → 十进制**表示与传输。数码管显示、0x0210 上传的卡号均为该换算值。0x0210 消息体中卡号字段为 **定长 10 字节 ASCII 十进制**（不足 10 位前导补 0），平台取消息体前 10 字节为卡号，其后为密码 ASCII。

## 3. 业务流程（重点：认证开门 + 疲劳驾驶计时）

```
刷卡 → 数码管显示卡号十进制（不开门、不发帧）
     → 输入密码（数码管逐位显示）
     → 按"确认" → 终端发送 0x0210（卡号十进制ASCII定长10位 + 密码ASCII）
     → 平台裁决，回 0x8110：
         体 0x00 = PASS → 舵机开门 + 数码管显示 PASS + 启动疲劳驾驶计时
         体 非00 = FAIL → 门不开，数码管显示 FAIL
     → 关车门（C 键）→ 停止计时，立即补发 0x0200
```

**硬性规则（平台侧判定依据）：**

1. **0x0210 仅在"刷卡 + 输入密码 + 确认"完整操作后发送，身份码（identity）必不为空**；刷卡单独不产生任何上报帧、不开门。
2. 未刷卡按确认 / 未输密码按确认，终端本地拒绝（不发帧），平台不会收到这两类请求。
3. **刷卡有效期 30 秒**：确认时若距刷卡已超 30 秒，终端仍会发送 0x0210，但**卡号字段为全 0（`0000000000`）**、仅携带密码——表示"密码操作有效但刷卡已过期"，平台按白名单查不到卡号即应回 0x8110 拒绝；重新刷卡即可恢复有效状态。
3. **开门/关门只以 0x8110 裁决 + 终端 0x0200 车门状态位为准**，没有独立的开门消息。
4. 疲劳驾驶计时：0x8110 PASS 开门即开始连续计时；**C 键关门停止计时**；连续驾驶达到阈值（默认 240 分钟，可配置）终端**本地**置疲劳报警并立即上报（0x0200 报警位），同时蜂鸣 + LED 报警序列；D 键解除后重新计时。

## 4. 上行消息（终端 → 平台）

| 消息 ID | 名称 | 频率 / 时机 | 消息体 |
|---|---|---|---|
| 0x0200 | 位置汇报 | 1 秒/帧；烟雾/车门/疲劳状态变化时**立即**补发 | 28B 基本信息 + 附加项 0x01 里程（4B，恒 0），共 34B |
| 0x0210 | 身份验证请求 | 刷卡+密码+确认后 | 卡号 10B ASCII 十进制（4B 大端 UID 换算，前导 0 补齐，如 `0219025168`）+ 密码 ASCII（**必非空**） |
| 0x0001 | 终端通用应答 | 收到平台每条 0x8xxx 必回 | 应答流水(2) + 应答ID(2) + 结果(1) |

## 5. 下行消息（平台 → 终端）

| 消息 ID | 消息体 | 终端行为 |
|---|---|---|
| 0x8001 | 通用应答 | 正常不打扰；result≠0 时串口提示 |
| 0x8110 | 第 1 字节：**0x00=PASS（开门）**，非 00=FAIL | PASS：舵机开门+显示 PASS+启动疲劳计时；FAIL：显示 FAIL。0x8110 是终端唯一接受的开门指令 |
| 0x8210 | 0x01=开启 / 0x00=解除 | 疲劳驾驶报警：蜂鸣间歇响 + LED 报警序列 + 0x0200 报警位 bit2 同步置位/清零 |
| 0x8811 | 0x01=开 / 0x00=关 | 蜂鸣器直控（与报警无关，测试用） |

## 6. 0x0200 字段语义（平台解析口径）

| 字段 | 口径 |
|---|---|
| 报警标志 | **疲劳驾驶 = `0x00000004`，烟雾超标（火警）= `0x00000001`**（按十六进制掩码对齐，勿按 bit 序号推算） |
| 状态位 | bit1=已定位、bit12=车门锁、bit13=车门1开、bit18=GPS 定位 |
| 速度 | 真实 GPS 地面速度，**整数 km/h**（平台无需终端侧判超速） |
| 时间 | BCD `YYMMDDhhmmss`，**UTC**（平台入库 +8）；未定位时用终端系统时间兜底 |
| 经纬度 | 度（十进制），GPS 实时；历史轨迹上传时为文件坐标并强制置已定位位 |
| 高程/方向 | 恒 0 |

**状态变化即时上报**：烟雾报警开/关、车门开（PASS/刷卡相关）/关（C 键）、疲劳报警开/关、D 键解除——每种状态变化都会立即补发一帧 0x0200（不等 1 秒心跳），平台按"最新位置覆盖"处理即可。

## 7. 帧格式（协议《JH车载定位数据协议_V0.1》）

```
7E | 消息ID(2) | 属性(2) | 手机号BCD(6) | 终端ID(6) | 流水号(2) | 消息包封装项(4，不分包恒0) | 消息体 | 校验(1) | 7E
```

- 校验：消息 ID 起至消息体末尾逐字节**异或**
- 转义：0x7E→`7D 02`、0x7D→`7D 01`（收发双向实现，头尾 7E 不转义）
- 消息体大端序

## 8. 变更记录（相对早期对接版本）

| 变更 | 说明 |
|---|---|
| **刷卡 30 秒有效期**（2026-09-22 晚） | 确认时距刷卡 >30s：0x0210 照发但卡号字段全 0（`0000000000`）仅带密码，平台按无卡拒绝；30s 内照常带卡号 |
| **历史轨迹带历史时间**（2026-09-22 晚） | `uppath` 支持"YYMMDD HH:MM:SS 经度 纬度 速度"格式，帧内时间用文件历史时间（北京时间已换算 UTC）、速度用文件值；坐标行内时间单调递增 |
| **卡号换算改版**（2026-09-22 晚） | 卡号由"4B 大端原始 UID"改为"4B 大端合成 32 位整数的**十进制**"：数码管与 0x0210 一致；**0x0210 卡号字段变为 10B ASCII 定长（前导 0 补齐）**，平台白名单/解析需同步更新（测试卡 `0D0E0F10` → `0219025168`） |
| **认证流程收紧**（2026-09-22） | 0x0210 必须卡号+密码齐全才发送（identity 必非空）；刷卡不再单独发帧/开门；开门唯一途径 = 0x8110 PASS |
| **疲劳驾驶本地计时** | PASS 开门后终端自行计时，达到阈值本地置疲劳报警并上报（不完全依赖平台下发 0x8210）；C 键关门停表，D 键解除重置 |
| **状态变化即时上报** | 烟雾/车门/疲劳状态变化立即补发 0x0200（原仅 1 秒心跳） |
| **历史轨迹已定位位** | uppath 上传的历史坐标点强制置"已定位"状态位（bit1+bit18），平台勿按未定位过滤 |
| 命令行 | `?/help`、`info`（含烟雾 ADC 原始值、驾驶计时）、`uppath [文件]`（无参数上传预存 `/arduino_drivers/path.txt`） |
| 显示 | 数码管轮播格式 `类型号-数值`（如 `2-00001` 车门开），10 秒空闲每 3 秒自动轮播；手动翻页控制台同步输出 |

## 9. 待平台确认 / 注意

1. 新平台联调前请确认服务已监听约定端口、防火墙放行（终端走 4G，**出口 IP 动态，勿按源 IP 白名单拦截**）。
2. 建议平台在收到 0x0210 时记录"卡号 + 车辆 + 时间"用于提醒推送（identity 必非空，可直接作双因子判定）。
3. 真实帧样例可由平台侧从服务器日志导出终端原始 hex，联调时双方核对编解码。
